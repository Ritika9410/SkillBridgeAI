# Deploy SkillBridge AI on Render

This project is a full Next.js app: the UI and `/api/*` routes run in one Node web service. MongoDB Atlas is the external database; Gemini is called from server routes. Do not deploy this as a static site.

## 1. Push the project to GitHub

Commit and push the project, including `package-lock.json`, `.node-version`, and `render.yaml`. `.env.local` is ignored by Git and must stay local. Never add it to a commit.

## 2. Create the Render service

In Render, choose **New → Blueprint**, connect the repository, and apply the `render.yaml` blueprint. It creates one Node web service in Singapore, builds with `npm ci && npm run build`, and starts the production Next.js server with `npm run serve`. The free plan may spin down when idle; choose an appropriate paid plan in Render if you need an always-on production service.

Render prompts for `MONGODB_URI` and `GEMINI_API_KEY`. `AUTH_SECRET` is generated by Render. These values are stored as service environment variables and are not committed to this repository.

## 3. Connect MongoDB Atlas

1. Create or select an Atlas cluster and a database user with access to the `skillbridgeai` database. Use a dedicated application user and a strong password.
2. After the first Render service is created, open its **Connect → Outbound** panel and copy the outbound IP ranges for the service's region.
3. Add those ranges to the Atlas project's **Network Access → IP Access List**. Avoid opening Atlas to `0.0.0.0/0` for a permanent deployment.
4. In the Render service's environment settings, set `MONGODB_URI` to the Atlas Node.js connection string. URL-encode any special characters in the database user's password. Set `MONGODB_DB` to `skillbridgeai` if it is not already present.

Render's shared outbound IP ranges may include multiple addresses; Atlas must allow the service's current Render ranges. Dedicated static outbound IPs are a Render paid workspace feature.

## 4. Connect Gemini

Create an API key in Google AI Studio, then set it as the Render service's `GEMINI_API_KEY`. Keep it server-only: do not rename it to `NEXT_PUBLIC_GEMINI_API_KEY` or place the value in frontend code. The existing Gemini requests are made by server-side API handlers. `GEMINI_MODEL` and `GEMINI_FALLBACK_MODEL` already have defaults in the blueprint and can be changed in Render if needed.

If a key is ever exposed, revoke it in Google AI Studio, create a replacement, update `GEMINI_API_KEY` in Render, and redeploy. Do not paste credentials into chat or commit them to the repository.

## 5. Check the deployment

Wait for the first build and deploy to finish, then open the service URL. Render checks `/login` for service health. Verify registration/login, saved profile data, and one Gemini-powered action. If MongoDB does not connect, check the URI, database user's permissions, and Atlas IP access list. If Gemini fails, check the key, quota, and configured model in Render's environment settings and inspect the service logs.

For later changes, push to the connected branch; Render builds and deploys the new commit. To rotate a secret, update the Render environment variable rather than editing `.env.example`.
